# Transport audit, 2026-10-10

Adversarial audit of the transport on branch feat/beyond-curl-cffi before the 2.0 work. Every finding was reproduced; the reproduction scripts live in the session scratchpad (audit-transport/) and are summarised here. Fix status is tracked in docs/STATE.md.

## Summary

Adversarial correctness audit of curl_reap's transport (http.py, h2engine.py, tls.py, aio.py, cache.py) on branch feat/beyond-curl-cffi. No source files were changed. 41 reproduction scripts live under the scratchpad audit-transport/ folder (shared harness.py provides FakeSocket, a GeneratorSocket for synthetic 70 MB bodies, an in-process hyper-h2 server behind a socket-like H2PipeSocket, and a raw loopback TCP server); every script was run and its observed output is recorded per finding.

September B-items: B13 (POST retry gating) and B28 (cookie path boundary) are fixed. B2, B14, B15, B16, B20 (all four sub-items), B24, B26, B30 and the fingerprint-table items are still open, each with file:line evidence and a running reproduction.

New defects, ranked. P1 (wrong results): six of eight YouTube cookies are silently dropped because SimpleCookie rejects any Set-Cookie carrying Partitioned, and an unknown valued attribute (Priority=High) becomes a phantom cookie that is replayed to the server; HTTP/2 responses are never content-decoded (gzip bytes returned as .content and written by download()); any h2 POST body above 16384 bytes raises a raw h2.exceptions.FrameTooLargeError (above 65535, FlowControlError) that bypasses TransportError and the retry loop; a server GOAWAY after a response leaves the h2 connection pooled and the next request dies with a raw h2 ProtocolError, never retried; a server push stream's END_STREAM is returned as the response body of the real request; download() over h2 buffers everything and fails above 64 MB; multi-member gzip bodies are truncated to the first member in both the buffered and streaming paths; a UTF-8 Location header is double-encoded (/caf%C3%83%C2%A9 instead of /caf%C3%A9); DiskCache.set truncates the body file in place before the meta swap, so concurrent readers get a fresh 200 with an empty body (771 torn reads in 1.5 s); download() replaces an existing file with a 503/404 body and returns without raising; proxy CONNECT omits :443 (RFC 9110 9.3.6 MUST send host:port).

P2 (robustness): no liveness check before pool reuse (server-closed keep-alive = TransportError on POST, a 0.5 s backoff penalty on GET), unbounded never-reaped pool (40 idle sockets after 40 parallel GETs), timeout is per socket op (0.5 s timeout happily waits 3 s for a dribbled body and 4.8 s across 5 redirect hops), no HTTP/1.1 size cap (70 MB buffered on all three framing paths), TLS handshake failures escape as raw ssl.SSLError/TimeoutError because _acquire runs outside the try block, bytes beyond Content-Length poison the next pooled response, HEAD+303 is rewritten to GET and downloads the body, headers={name: None} cannot drop a profile header, download() raises ValueError on a malformed Content-Length, Retry-After: inf crashes with OverflowError and 99999999 sleeps for real, close() never sends GOAWAY, h2 download writes a redirect body to the sink.

P3: _release/close() race leaks a live socket into a closed pool, 101 responses are pooled as HTTP/1.1, trailer handling differs between buffered and streaming paths (a trailer can inject Location/Content-Encoding), Transfer-Encoding without chunked ignored, Connection token lists not parsed, Secure cookies accepted from http origins, IDNA host vs punycode Domain/origin mismatches, lenient int() parsing (Content-Length: 1_0 accepted), download meta claims saved_to with no file, h2 set-cookie header keeps only the last value, eager .text decode doubles memory for binaries, aio cancellation cannot stop the worker, plus the B24/B26/B30/fingerprint items.

Verified OK (no finding): CL+TE both present (chunked wins), 1xx interim skipped, HEAD/304 bodies not read, HTTP/1.0 not pooled, IDNA Host + IPv6 bracketing + request-target percent-encoding, relative Location with query, 303 after PUT, 307 body kept, hop cookie default-path, Secure cookies withheld over http, Max-Age negative / past Expires, empty POST Content-Length: 0, bytes/str/json/params encoding, auth kwarg precedence, verify in pool key, socket closed when wrap_socket raises, h2 WINDOW_UPDATE on both stream and connection windows (300 KB body), h2 SETTINGS ack, h2 103 interim.

## Findings

### F02 [P1] Set-Cookie with Partitioned is dropped whole; unknown valued attributes become phantom cookies that are replayed

- Location: `curl_reap/http.py:434`
- Evidence: http.py:434-438 _parse_set_cookie feeds the whole header to http.cookies.SimpleCookie.load inside try/except Exception: return (). SimpleCookie returns nothing for an unreserved flag attribute (Partitioned) and treats an unreserved key=value (Priority=High) as a second cookie. Live: YouTube sends 8 Set-Cookie lines, 6 carry Partitioned (YSC, VISITOR_INFO1_LIVE, VISITOR_PRIVACY_METADATA, __Secure-YNID, __Secure-ROLLOUT_TOKEN, ...) and the jar keeps only GPS and __Secure-BUCKET.
- Reproduction result: 'sid=abc; ...; Partitioned' -> jar={} replayed=[]; 'sid=abc; ...; Priority=High' -> jar={'sid':'abc','Priority':'High'} and the next request sends 'Cookie: sid=abc; Priority=High'; 'name=John Doe' -> dropped. Live youtube.com: 8 cookies on the wire, 2 kept, every drop is a Partitioned line.
- Suggested fix: Replace SimpleCookie with a hand-written RFC 6265bis Set-Cookie parser: split on ';', first pair is name=value (value may contain spaces/commas), remaining pairs are attributes matched case-insensitively against a known set, unknown attributes ignored.

### F-B2 [P1] HTTP/2 responses are returned and saved undecoded (gzip bytes in .content/.text and in download() files)

- Location: `curl_reap/http.py:1012`
- Evidence: http.py:1012-1014 passes the raw h2 body into _RawResponse; _decode_content is only called at :832 (1.1 path); :953-960 writes response.content to the sink without _body_streamer. Every profile advertises Accept-Encoding: gzip, deflate (tls.py:113/145/158).
- Reproduction result: content == raw gzip bytes True, text starts with '\x1f\x8b', download() wrote raw gzip True, meta bytes 50 (compressed length).
- Suggested fix: In _h2_exchange run _decode_content(content, ci.get('Content-Encoding')) and, for sinks, stream DATA frames through _body_streamer into the part file instead of buffering.

### F04 [P1] h2 request bodies above 16384 bytes raise raw hyper-h2 exceptions from Session.post

- Location: `curl_reap/h2engine.py:90`
- Evidence: h2engine.py:90 self._conn.send_data(stream_id, body, end_stream=True) sends the whole body in one call; hyper-h2 raises FrameTooLargeError above max_outbound_frame_size (16384) and FlowControlError above the stream window (65535). http.py:976-979 only converts OSError/ssl.SSLError, and Session.request :1492 only retries TransportError/OSError/SSLError, so the h2 exception escapes raw.
- Reproduction result: POST 16384 bytes -> 200; POST 16385 bytes -> h2.exceptions.FrameTooLargeError 'Cannot send frame size 16385, max frame size is 16384' (TransportError? False); POST 70000 bytes -> h2.exceptions.FlowControlError 'Cannot send 70000 bytes, flow control window is 65535'.
- Suggested fix: Chunk the body by min(local_flow_control_window(stream_id), max_outbound_frame_size), pump recv/WindowUpdated events while the window is 0, and wrap h2.exceptions.H2Error into TransportError in _h2_exchange.

### F05 [P1] Server GOAWAY leaves the h2 connection pooled; the next request raises a raw h2 ProtocolError that is never retried

- Location: `curl_reap/http.py:952`
- Evidence: http.py:952 reusable = True after every h2 exchange. h2engine.py:122-127 returns at StreamEnded and drops the remaining events of the same recv (the GOAWAY), and :105-130 has no ConnectionTerminated branch. hyper-h2 has already moved to CLOSED, so send_headers on the pooled connection raises h2.exceptions.ProtocolError, which Session.request :1492 does not catch. When the GOAWAY arrives in a later segment the loop instead hits recv()==b'' and raises TransportError 'HTTP/2 connection closed mid-response' (retried for GET only after a backoff, raised for POST).
- Reproduction result: first GET ok, pooled after GOAWAY: 1, second GET raised h2.exceptions.ProtocolError 'Invalid input ConnectionInputs.SEND_HEADERS in state ConnectionState.CLOSED', isinstance TransportError False, not retried.
- Suggested fix: Handle ConnectionTerminated in the h2 read loop (mark the protocol dead, return reusable=False), check conn.h2 liveness before reuse in _acquire, and transparently retry a request whose stream_id > last_stream_id on a fresh connection since the server guarantees it was not processed.

### F06 [P1] A server push stream's END_STREAM is returned as the response to the real request

- Location: `curl_reap/h2engine.py:122`
- Evidence: h2engine.py:106-127: ResponseReceived overwrites status/headers, DataReceived appends to chunks and StreamEnded returns, none of them compares event.stream_id to the stream_id obtained at :74; H2Configuration at :34-35 keeps hyper-h2's client default ENABLE_PUSH=1 (the context's akamai string shows 2:1). Rare in 2026 (Chrome and nginx dropped push) but Apache mod_http2 with H2Push still does it.
- Reproduction result: requested /page whose real answer is 404 text/html '<h1>real page</h1>' -> returned status 200 content-type text/css body b'PUSHED-CSS'.
- Suggested fix: Set ENABLE_PUSH=0 in local settings (matches Chrome 2:0), reset any PushedStreamReceived stream with RST_STREAM, and filter every event on event.stream_id == stream_id.

### F07 [P1] download() over HTTP/2 buffers the whole body in memory and fails above 64 MB

- Location: `curl_reap/http.py:953`
- Evidence: http.py:948-960: _h2_exchange returns the fully buffered content, then the sink is written from memory; h2engine.py:19 _MAX_BODY_BYTES = 64 MiB and :116-118 raise once exceeded. The download() docstring at :1544-1550 promises constant memory whatever the size.
- Reproduction result: h2 download of 67108865 bytes raised TransportError 'HTTP/2 body exceeds 67108864 bytes' after 3.1 s, no file written; h2 download of 20 MB: peak traced heap 60 MB versus a 256 KB streaming buffer on the 1.1 path.
- Suggested fix: Give H2Protocol.request a write callback (or a generator of DATA chunks) so _single_request can stream h2 DATA frames through _body_streamer into the part file; apply the cap only when no sink is given.

### F01 [P1] Multi-member gzip bodies are silently truncated to the first member

- Location: `curl_reap/http.py:248`
- Evidence: http.py:248 zlib.decompress(decoded, 16 + zlib.MAX_WBITS) one-shot stops at the first gzip member and ignores trailing data (confirmed with zlib directly: b'first-member-'); _StreamDecoder.feed at :406-416 never looks at decompressobj.unused_data so the streaming path drops it too. gzip.decompress handles multi-member correctly; curl/browsers also concatenate members.
- Reproduction result: expected b'first-member-second-member', got b'first-member-' (truncated True); download() file b'first-member-', meta bytes 13.
- Suggested fix: Loop while decompressobj.eof and unused_data: start a new decompressobj on unused_data; in the one-shot path use the same loop (or gzip.decompress for gzip).

### F03 [P1] UTF-8 bytes in a Location header are double-encoded on the redirect request

- Location: `curl_reap/http.py:769`
- Evidence: http.py:769 header values are decoded as latin-1, _Transport.request :1069 urljoin()s the mojibake string, and _request_target :205 quote()s it as UTF-8, so each original byte becomes two percent-escapes. requests re-encodes Location as latin-1 then decodes as UTF-8 for exactly this reason.
- Reproduction result: server Location b'/caf\xc3\xa9/\xe6\x97\xa5\xe6\x9c\xac' -> second request line 'GET /caf%C3%83%C2%A9/%C3%A6%C2%97%C2%A5%C3%A6%C2%9C%C2%AC HTTP/1.1' (should be /caf%C3%A9/%E6%97%A5%E6%9C%AC); response.url 'http://u.test/cafÃ©/æ\x97¥æ\x9c¬'.
- Suggested fix: Before urljoin: location = location.encode('latin-1'); try location.decode('utf-8') except UnicodeDecodeError: percent-encode the raw bytes; apply the same treatment in _h2_exchange (h2 header_encoding='latin-1').

### F08 [P1] DiskCache.set truncates the body file in place before the meta swap; concurrent readers get a fresh 200 with an empty body

- Location: `curl_reap/cache.py:87`
- Evidence: cache.py:87-88 open(body_p, 'wb').write(...) rewrites the body file in place while the old meta (saved_at fresh) is still live; the meta is swapped atomically only afterwards at :89-94; _read at :41-44 reads meta then body with no consistency check; the tmp name at :86 is fixed so two writers also collide.
- Reproduction result: get() while the body file is open for write returns status 200 content length 0 as a fresh hit; writer/reader threads for 1.5 s: 771 torn reads, all length 0.
- Suggested fix: Write the body to a unique temp file (tempfile.NamedTemporaryFile(dir=...)) and os.replace it, then write/replace the meta; store the body length (or a digest) in the meta and reject entries whose body size disagrees.

### F09 [P1] download() replaces an existing file with the body of a 4xx/5xx response and returns without raising

- Location: `curl_reap/http.py:786`
- Evidence: http.py:786 streams any non-redirect status into the part file, :807 os.replace(part_path, sink) commits it, and Session.request :1519-1526 returns the Response with meta saved_to/bytes for any status; raise_for_status is never consulted. After retries are exhausted a 503 maintenance page lands in the user's path.
- Reproduction result: existing dataset.csv (19 KB of good rows) -> after 3 x 503 the file contains b'<h1>maintenance</h1>', status 503, no exception, meta {'saved_to': ..., 'bytes': 20}.
- Suggested fix: Only os.replace into the sink for 2xx (configurable, e.g. download(..., ok_only=True) default), otherwise discard the part file, keep the body in memory for diagnostics and raise HTTPStatusError or return the Response without touching the path.

### F12 [P1] Proxy CONNECT omits the port for 443 (RFC 9110 9.3.6 requires host:port)

- Location: `curl_reap/http.py:695`
- Evidence: http.py:695 authority = _authority(host, port, 443) and _authority at :197-201 drops the port when it equals the default, so the tunnel request is 'CONNECT example.com HTTP/1.1'. RFC 9110 9.3.6: the client MUST send only the host and port number of the tunnel destination, separated by a colon; curl always sends host:443. Squid's CONNECT URL parser requires the host:port form (sscanf '%[^:]:%d' < 2 is treated as an invalid URL).
- Reproduction result: CONNECT sent: b'CONNECT example.com HTTP/1.1\r\nHost: example.com\r\n\r\n'; with an explicit non-default port the form is correct: b'CONNECT [2001:db8::1]:8443 HTTP/1.1'.
- Suggested fix: Use '%s:%d' % (bracketed_host, port) unconditionally for the CONNECT target and its Host header (keep _authority for the origin Host header).

### F-B14 [P2] No liveness check before pool reuse; pool unbounded and never reaped

- Location: `curl_reap/http.py:659`
- Evidence: http.py:659-670 and :736-741 (see B14 above). A server-closed keep-alive costs a TransportError on POST (not retried by default) and a backoff sleep plus reconnect on GET; curl probes the socket before reuse.
- Reproduction result: POST on stale conn -> TransportError; GET -> succeeds after sleeping 0.52 s; 40 idle sockets remain after 40 parallel GETs.
- Suggested fix: In _acquire: select/poll the socket with timeout 0 (readable == EOF/garbage -> close and discard), record a release timestamp and drop connections idle longer than ~60 s, cap per-key pool size (e.g. 10) and close the surplus.

### F-B15 [P2] timeout is a per-socket-operation value, not a request deadline; every redirect hop gets a fresh budget

- Location: `curl_reap/http.py:666`
- Evidence: http.py:666, :684-688 settimeout; :1042-1057 same timeout per hop.
- Reproduction result: timeout=0.5: dribbled 10-byte body completes in 3.03 s; 5 hops of 0.35 s plus the drip complete in 4.81 s; no timeout raised.
- Suggested fix: Compute deadline = monotonic() + timeout once in Session.request, pass remaining time into every settimeout/connect call and raise TransportError('request deadline exceeded') when it reaches 0; keep a separate optional per-op timeout.

### F-B16 [P2] No response size cap on HTTP/1.1

- Location: `curl_reap/http.py:824`
- Evidence: http.py:824, :826, :871-894 unbounded; only h2engine.py:19 caps.
- Reproduction result: 73400320 bytes buffered on all three framing paths.
- Suggested fix: Add Session(max_body_bytes=64 MiB) applied in read_exact/read_to_close/_read_chunked (not to sinks) and raise TransportError when exceeded, matching the h2 cap.

### F38 [P2] TLS handshake failures escape as raw ssl.SSLError / TimeoutError instead of TransportError

- Location: `curl_reap/http.py:945`
- Evidence: http.py:945 conn = self._acquire(...) executes before the try at :947 whose except at :976-979 converts OSError/ssl.SSLError into TransportError; _connect :708-713 only closes the socket and re-raises. Session.request :1492 retries them (they are OSErrors) but the final exception type is ssl.SSLError, so 'except curl_reap.TransportError' misses certificate and handshake failures.
- Reproduction result: fake cert failure -> ssl.SSLCertVerificationError (TransportError False); fake handshake timeout -> builtins.TimeoutError; live https://self-signed.badssl.com/ and https://expired.badssl.com/ -> ssl.SSLError '[SSL: SSLV3_ALERT_HANDSHAKE_FAILURE]' (TransportError False).
- Suggested fix: Move _acquire inside the try, or wrap wrap_socket/CONNECT in _connect with except (OSError, ssl.SSLError) as exc: raise TransportError('TLS handshake with %s failed: %s') from exc.

### F37 [P2] Bytes beyond Content-Length stay in the reader buffer and poison the next response on the pooled connection

- Location: `curl_reap/http.py:824`
- Evidence: http.py:824 read_exact(length) leaves any excess in _BufferedSocket.buffer (:273-304) and :736-741 pools the connection without checking that the buffer is empty; libcurl logs 'Excess found' and discards.
- Reproduction result: first: b'ok'; second request on the same connection: TransportError "malformed HTTP status line 'EXTRAHTTP/1.1 200 OK'".
- Suggested fix: In _release (or _response) treat a non-empty conn.reader.buffer as not reusable and close the connection.

### F10 [P2] HEAD followed by 303 is rewritten to GET and downloads the body

- Location: `curl_reap/http.py:1077`
- Evidence: http.py:1077-1079 turns any 303 into GET regardless of the original method; RFC 9110 15.4.4 allows GET or HEAD and curl keeps HEAD.
- Reproduction result: request lines ['HEAD /thing HTTP/1.1', 'GET /big HTTP/1.1'], final status 200 with 5000 body bytes received for a HEAD.
- Suggested fix: if status == 303 and current_method != 'HEAD': current_method = 'GET' (same for the 301/302 POST rule).

### F11 [P2] headers={name: None} cannot remove a profile header

- Location: `curl_reap/http.py:1443`
- Evidence: Session.request :1443 merges session+request headers with _merge_headers, which at :176-180 consumes the None marker (continue) when the name is absent; _single_request :923-924 then merges profile.headers under the already-filtered custom headers, so Accept-Encoding/Accept-Language from the profile survive. Session-level headers are removed correctly.
- Reproduction result: headers={'Accept-Encoding': None, 'X-Session': None, 'Accept-Language': None} -> wire still has 'Accept-Encoding: gzip, deflate' and 'Accept-Language: en-US,en;q=0.9' (X-Session removed).
- Suggested fix: Carry None markers through _merge_headers output (or merge profile headers first in Session.request so a single merge sees them).

### F13 [P2] download() raises ValueError (not TransportError, not retried) on a malformed Content-Length

- Location: `curl_reap/http.py:796`
- Evidence: http.py:796 length = int(headers.get('Content-Length')) has no try/except, unlike the buffered path at :818-823.
- Reproduction result: get -> curl_reap.http.TransportError 'invalid Content-Length header'; download -> builtins.ValueError "invalid literal for int() with base 10: 'abc'".
- Suggested fix: Factor a _content_length(headers) helper that validates (digits only, non-negative, single value) and use it in both paths.

### F14 [P2] Retry-After is uncapped: 'inf'/1e400 crash with OverflowError, 99999999 sleeps for real

- Location: `curl_reap/http.py:103`
- Evidence: retry_after_seconds :55-66 returns max(0.0, float(value)) so 'inf' and '1e400' yield inf; RetryPolicy.delay :103-107 returns it verbatim (documented at :75-76 as not capped by max_backoff); Session.request :1516 time.sleep(...) -> OverflowError for inf, multi-year sleep otherwise.
- Reproduction result: Retry-After: inf -> OverflowError 'timestamp too large to convert to C PyTime_t'; 1e400 -> same; 99999999 -> slept 99999999.0 s (sleep stubbed).
- Suggested fix: Reject non-finite values in retry_after_seconds (math.isfinite) and add RetryPolicy(max_retry_after=...) defaulting to something like 120 s; beyond it, stop retrying and return the 429/503 to the caller.

### F-B20a [P2] Session.close() never sends GOAWAY on h2 connections; H2Protocol.close is dead code

- Location: `curl_reap/http.py:356`
- Evidence: http.py:356-363 _Connection.close only closes the socket; h2engine.py:44-53 is never called.
- Reproduction result: frames sent by close(): [], server saw ConnectionTerminated: False, socket closed: True.
- Suggested fix: In _Connection.close call self.h2.close() when self.h2 is not None (it sends GOAWAY then closes the socket).

### F-B20d [P2] h2 download writes a redirect hop's body to the sink before the redirect is evaluated

- Location: `curl_reap/http.py:953`
- Evidence: http.py:953-960 writes for any status; the 1.1 path guards at :786.
- Reproduction result: h2 download with max_redirects=0 raised 'too many redirects' and left the file with b'<html>moved</html>'; 1.1 path left no file.
- Suggested fix: Guard the h2 sink write with status not in _REDIRECT_STATUSES (and, per F09, with 2xx).

### F30 [P3] _release reads _closed outside the lock: a close() in between leaves a live socket in the cleared pool

- Location: `curl_reap/http.py:737`
- Evidence: http.py:737 checks self._closed, then :740-741 takes the lock and appends; close() at :1088-1094 sets _closed and clears the pool under the lock, so the interleaving check -> close() -> append leaks the connection.
- Reproduction result: transport closed: True, pool entries after close(): 1, that socket closed: False.
- Suggested fix: Move the _closed check inside the with self._lock block in _release.

### F27 [P3] A 101 Switching Protocols response is returned as final and the connection is pooled as HTTP/1.1

- Location: `curl_reap/http.py:777`
- Evidence: http.py:777 lets 101 through, :781-782 marks it bodyless and reusable, so the tunnel bytes are read as the next response.
- Reproduction result: status 101, pooled: 1; next request on that socket: TransportError 'connection closed before the response was complete'.
- Suggested fix: Mark 101 responses reusable=False (and refuse to pool when the request carried Upgrade).

### F21 [P3] Chunked trailers are folded into headers on the buffered path (trailer can inject Location/Content-Encoding) and discarded on the streaming path

- Location: `curl_reap/http.py:889`
- Evidence: http.py:883-891 setdefault()s trailer fields into headers before :832 decodes and :1063 reads Location; _read_chunked_into :858-864 drops them. RFC 9110 6.5.1 forbids trailers for framing/routing fields.
- Reproduction result: buffered: trailer 'Content-Encoding: gzip' decoded the body, X-Trailer visible; streaming: X-Trailer None and the file holds raw gzip; a 302 whose Location arrives only as a trailer is followed.
- Suggested fix: Keep trailers in a separate response.trailers mapping on both paths and never let them affect framing, decoding or redirects.

### F31 [P3] Transfer-Encoding without 'chunked' (e.g. gzip) is ignored and the body is returned encoded

- Location: `curl_reap/http.py:815`
- Evidence: http.py:815-817 only checks for the 'chunked' substring; other transfer codings fall through to Content-Length framing with no decoding (RFC 9112 6.1 says the message length is then until close).
- Reproduction result: content starts with gzip magic, decoded? False.
- Suggested fix: Parse the TE token list; reject or decode non-chunked codings and treat Content-Length as absent when TE is present.

### F32 [P3] Connection header compared as a whole string, so 'close, foo' or 'keep-alive, close' keeps the socket pooled

- Location: `curl_reap/http.py:829`
- Evidence: http.py:829-831 connection_header == 'close'.
- Reproduction result: 'Connection: close' -> pooled 0; 'Connection: close, foo' -> pooled 1; 'Connection: keep-alive, close' -> pooled 1.
- Suggested fix: Tokenise on commas and test 'close' in tokens.

### F35 [P3] Secure cookies set over plain http are accepted into the jar

- Location: `curl_reap/http.py:539`
- Evidence: CookieJar.absorb :539-582 never looks at parts.scheme; RFC 6265bis 5.5 step 14 (Leave Secure Cookies Alone) says reject.
- Reproduction result: jar after Secure cookie from http origin: {'sid': 'x'}, replayed on https: 'sid=x'.
- Suggested fix: In absorb skip specs with secure=True when the origin scheme is not https.

### F15 [P3] IDNA hosts: Unicode hostname compared with punycode Domain attribute and origin

- Location: `curl_reap/http.py:542`
- Evidence: absorb :541-542 uses parts.hostname (Unicode) while the wire host at :905 is punycode, so Domain=xn--... from the server never matches; _origin :1023-1027 also compares un-normalised hostnames so a redirect between the two spellings strips auth/cookies.
- Reproduction result: Domain=xn--bcher-kva.example cookie stored: {'hostonly': '2'} (domain cookie dropped); replay on punycode spelling ''; _origin unicode == punycode ? False.
- Suggested fix: Normalise hostnames with .encode('idna').decode() (lowercased) in absorb, header_for and _origin.

### F16 [P3] Content-Length and chunk-size parsed with int(), accepting '_', '+' and '0x'

- Location: `curl_reap/http.py:819`
- Evidence: http.py:819 int(value), :853 and :877 int(size_text, 16); Python accepts '1_0', '+10', '0x5'; strict parsers (proxies) reject them, a classic desync surface.

- Suggested fix: Validate with re.fullmatch(rb'[0-9]+') / rb'[0-9A-Fa-f]+' before converting.

### F18 [P3] download() reports meta saved_to/bytes when no file was written (204, 304, redirects with allow_redirects=False)

- Reproduction result: 204 -> meta {'saved_to': path, 'bytes': 0}, file exists False; 302 allow_redirects=False -> same.

### F23 [P3] Over h2, response.headers['set-cookie'] keeps only the last cookie

- Location: `curl_reap/http.py:1009`
